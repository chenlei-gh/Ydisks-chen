# 单商品发布最终请求闸门重试保护

## 背景

单商品适配器原有逻辑在 `SessionExpiredError` 后恢复凭证并再次调用完整 `PublishItem`。MTOP 的 `BeforePublish` 钩子位于图片上传/类目准备之后、最终商品创建请求之前。若第一次调用已经越过该钩子，响应错误本身不足以证明远端没有创建商品，因此自动重放存在重复创建风险。

## 当前保护

- 应用层 `PublishInput.BeforePublish` 回调透传到 MTOP 的最终请求前钩子。
- 适配器在该钩子成功返回后记录 `publishStarted`；随后即使遇到 Session 过期，也不再自动重放。
- 若 Session 过期发生在最终请求闸门之前，仍允许一次凭证恢复重试，因为此时最终商品创建请求尚未发出（图片上传可能已发生，仍可能产生孤立上传资源）。
- 新增适配器回归测试覆盖“最终请求闸门已通过 + Session 过期”场景，要求发布方法调用次数为 1。

## 限制

当前 HTTP 调用尚未携带稳定 operation ID，且回调尚未连接持久化操作仓储。因此这只是消除一个隐藏的自动重放路径，并为后续 `prepared -> started` 数据库检查点提供接入点；它尚不能解决进程硬中断、客户端超时后的查询/人工核对问题，也不代表真实平台行为已验证。

## 持久化操作账本接入

PR #7 将上述最终请求闸门接入持久化操作账本：

- 新请求先创建 prepared 记录；最终创建请求前通过 BeforePublish 原子推进为 started。
- 平台返回带商品 ID 的成功结果后，先将应用层结果保存为 remote_confirmed，再执行本地商品 Upsert；Upsert 成功后推进 local_confirmed。
- 如果最终创建请求闸门已经通过但调用结果不明确，记录为 unknown。started 和 unknown 都不允许同一操作 ID 自动重发。
- remote_confirmed 的再次提交只恢复本地 Upsert；local_confirmed 直接返回已确认结果。
- 服务端计算规范化商品字段、规格、商品图片和规格图片内容哈希的 SHA-256 指纹。同一操作 ID 携带不同指纹时拒绝，避免把一个操作 ID 用于不同商品内容。
- HTTP 提供用户归属隔离的状态查询；前端按账号和完整表单指纹在 sessionStorage 保存操作 ID。图片字节和 Cookie 不写入浏览器存储。

## 验证边界与未解决风险

- 应用层回归测试覆盖未知结果不重发、远端确认后的本地恢复、不同请求指纹冲突；CI 尚需确认通过。
- 状态账本只能保证本地对同一 operation ID 的并发闸门互斥，不是闲鱼远端 exactly-once。当前没有证据表明闲鱼创建接口支持幂等键或按客户端请求 ID 查询。
- 进程在远端已创建但写入 remote_confirmed 前硬中断，数据库仍会停留在 started；该状态会阻止自动重发，但需要人工核对。
- 图片上传和类目准备发生在最终创建闸门之前；这些准备步骤失败可能留下平台孤立图片资源。
- 浏览器刷新后，前端可从 sessionStorage 找回操作 ID，但要重建相同指纹仍需恢复相同表单并重新选择相同图片。sessionStorage 不存放商品图片或 Cookie。
- 真实闲鱼账号、买家、商品和订单测试仍暂停；代码与 CI 结果不能替代平台实测。
